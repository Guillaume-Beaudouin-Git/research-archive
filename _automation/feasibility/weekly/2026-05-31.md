## Top 3 handlers à construire en priorité

### Priorité 1 — RegimeFilterHandler (implémentation complète)

**Impact estimé** : 7+ REQUIRES_HUMAN par semaine débloqués → certains en FAIL_A (items non-trading), d'autres en vrai test statistique.

**Ce qu'il faut implémenter** :
1. Filtrage amont : si l'article ne décrit pas un overlay sur Strategy A (crypto TSMOM), rediriger vers FAIL_A NON_TESTABLE plutôt que REQUIRES_HUMAN.
2. Pour les vrais overlays TSMOM : régimes vol_low / trend_up / combined déjà définis dans le stub ; wrapper les tests dans les WF folds (pas de look-ahead) ; bootstrap conditionnel par régime.
3. Gate : ΔSharpe > +0.1 + bootstrap p < 0.05 (déjà spécifié dans README).

**Effort** : 2 jours selon la doc du handler lui-même.

### Priorité 2 — TAA/GTAA Multi-Asset Handler

**Impact estimé** : 2–4 REQUIRES_HUMAN/semaine débloqués (dual momentum, global tactical allocation, risk parity).

**Pourquoi** : les articles GTAA/TAA représentent une famille cohérente (Faber Timing Model, dual momentum, asset class momentum). Un handler dédié pourrait tester un signal GTAA sur ETFs (SPY/IEF/GLD/DBC) avec les gates standard.

**Contrainte** : data ETF via yfinance, coûts 0.05–0.10% RT, N<12 actifs (L6 non applicable car CS cross-sectional pas concerné par N≥30 pour GTAA).

### Priorité 3 — Academic-Methods Filter (ajout au GenericHandler)

**Problème** : des papers d'économétrie pure (Tweedie, conformal prediction, partial identification) matchent les patterns COMPLEX dans le GenericHandler mais n'ont **aucun signal de trading testable**. Ils devraient être éjectés en FAIL_A NON_TESTABLE avant d'atteindre le REQUIRES_HUMAN.
