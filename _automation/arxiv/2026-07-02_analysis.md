# Alpha analysis — 2026-07-02

## [1] End-to-End Parametric Portfolio Policies for Cross-Asset Futures Timing

**Link** : https://arxiv.org/abs/2607.00475
**Strategy fit** : A (TSMOM benchmark) | Cross-strategy (Commodities XS active research, Strategy D infra)

### 1. Edge identifié
Le papier ne propose pas un signal nouveau mais compare deux paradigmes : (a) forecast-then-optimize
(règles simples : equal-weight, risk parity, TSMOM) vs (b) politique bout-en-bout qui mappe l'état de
marché directement vers des poids de portefeuille via une perte Sharpe différentiable (LSTM,
transformer). Le mécanisme économique invoqué n'est pas une nouvelle prime de risque mais un gain
d'efficience d'allocation : en évitant l'étape intermédiaire de prévision de rendement, le modèle
bout-en-bout pourrait mieux exploiter les corrélations cross-asset et le tuning implicite du sizing
pour le ratio de Sharpe. L'univers (16 futures CME les plus liquides) est choisi explicitement pour
exclure une explication par prime d'illiquidité — donc si edge il y a, il vient de la structure du
signal/l'allocation, pas de friction de marché exploitée.

### 2. Évidence empirique
- **Univers testé** : 16 futures CME les plus liquides (classes d'actifs mixtes — actions, taux,
  FX, matières premières a priori, non détaillé dans l'abstract tronqué).
- **Métriques** : perte Sharpe différentiable en entraînement ; comparaison brute (gross) vs
  post-coûts. Pas de Sharpe/t-stat chiffré dans l'abstract disponible (tronqué à 1058 caractères
  côté cache VPS) — chiffres précis (Sharpe ratios, drawdown) non extraits, PDF non accessible
  (réseau bloqué, cf. note sortie 1).
- **Méthodologie de validation** : out-of-sample déclaré explicitement ("comparable out-of-sample"),
  mais le nombre de folds / walk-forward n'est pas visible dans l'abstract — impossible de vérifier
  le respect du seuil ≥5 folds ici sans le PDF complet.
- **Robustesse** : le résultat clé est justement une étude de sensibilité aux coûts de transaction —
  point positif méthodologique (LSTM vs transformer divergent uniquement une fois les coûts intégrés,
  le transformer étant plus économe en turnover). Pas d'information sur les régimes de marché testés.

  perte Sharpe différentiable, infra que je n'ai pas construite (nécessiterait training pipeline

- **Coût d'implémentation** : HIGH — entraînement de réseaux de neurones bout-en-bout avec perte
  Sharpe différentiable est un changement d'infra complet vs les signaux fermés actuels (A, C, D
  candidats). Risque d'overfitting élevé sur un univers de 16 instruments sans garantie de walk-forward
  rigoureux vérifiable depuis l'abstract seul.
- **Conflit stratégies existantes ?** Non direct, mais chevauche l'axe de recherche Commodities XS

  mais reste dans la même famille de risque (timing cross-asset, β-exposure potentielle non testée

- **Data requis** : à fetcher — 16 futures CME liquides, historique suffisant pour entraînement ML

### 4. Honest skeptic check
1. **Data snooping / tuning implicite** : une perte Sharpe différentiable optimisée directement sur
   l'OOS déclaré peut masquer un choix d'architecture/hyperparamètres sélectionné a posteriori sur le
   même historique — l'abstract ne mentionne aucune procédure de walk-forward expanding ni de
   split IS/OOS temporellement propre, seulement "out-of-sample" générique.
2. **Univers restreint (16 instruments)** : sous le seuil N≥30 requis pour toute affirmation
   cross-sectionnelle robuste dans ma méthodologie (Lesson 6) — même si l'univers est choisi pour sa
   liquidité, 16 instruments laissent une marge de overfitting élevée pour un modèle à des milliers
   de paramètres (LSTM/transformer).
3. **Coûts "modérés" mal définis** : "matches or exceeds equal weighting through moderate cost" est
   vague — sans le chiffre exact de coût par trade (bps RT) et sans stress test à 2-3× coût (cf.
   L19/L33 sur la sensibilité des edges CME/CFD au tier de coût réel), impossible de savoir si l'edge
   survit aux coûts futures réalistes ($2.15 RT MNQ ou équivalent gros contrats).

### 5. Décision proposée
**REFERENCE_ONLY.** Le papier est méthodologiquement intéressant (benchmark TSMOM sur futures
liquides, sensibilité aux coûts) mais ne fournit pas assez de détail empirique vérifiable (pas de
Sharpe/t-stat chiffré accessible, pas de confirmation walk-forward ≥5 folds, univers <30) pour
engager un TEST_NOW, et l'infra ML bout-en-bout est un changement d'architecture HIGH-cost hors
scope d'un cycle de recherche standard. À garder comme référence pour la recherche Commodities XS
active et pour toute future comparaison ML-vs-rule-based sur futures liquides.
